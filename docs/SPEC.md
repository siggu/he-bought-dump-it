# 그가 샀습니다 — 주식 모의 투자 서비스 기획서

> 한 종목에 올인하고, 파산하면 게임으로 다시 일어서는 모의 투자 서비스

## 0. 확정된 결정 사항

| 항목 | 결정 |
| --- | --- |
| 시세 데이터 | 실제 국내 주식 (한국투자증권 Open API). 키가 없으면 모의 시세로 대체 |
| 메인 종목 변경 | 보유 수량 0일 때만, 7일에 1회 (3.2의 A안) |
| 파산 기준 | 총자산 < max(1주 가격, 10만원). 재기 기준은 현금 ≥ max(1주 가격, 100만원) |
| 월급 | 매달(KST) 1회 1,000,000원 수령 |
| 미니게임 | 난이도 3단계(쉬움/보통/어려움), 하루 3회·한 달 10회 (3.6 참고) |
| 인프라 | Cloudflare Workers + Durable Objects + D1, GitHub Actions로 자동 배포 |

세부 구현과 배포 방법은 루트의 README.md를 참고하세요.

## 1. 핵심 컨셉

| 항목 | 내용 |
| --- | --- |
| 거래 종목 | 계정당 **1개 종목(메인 종목)** 만 매매 가능 |
| 시세 | 메인 종목 + 현재 보고 있는 검색 종목만 **실시간** 스트리밍 (트래픽 절감) |
| 재화 | 페이지 내 가상 화폐 (예: `덤프코인`, 단위 `D`) — 현금 환전 불가 |
| 파산 | 총자산이 기준 이하가 되면 매매 잠금 → **미니게임**으로 재화 획득 후 복귀 |
| 계정 | 회원가입 / 로그인 / 로그아웃 |

## 2. 사용자 흐름

```
회원가입 ─▶ 메인 종목 선택(1회) ─▶ 초기 자금 지급(예: 10,000,000 D)
                │
                ▼
        [대시보드: 메인 종목 실시간 차트 + 매수/매도]
                │                     │
                │ 검색                 │ 총자산 < 파산 기준
                ▼                     ▼
   [다른 종목 상세: 실시간 시세,      [파산 화면: 매매 잠금]
    조회 전용, 매매 불가]                   │
                                          ▼
                                   [미니게임으로 재화 획득]
                                          │
                                          ▼
                                   기준 금액 회복 시 매매 재개
```

## 3. 기능 명세

### 3.1 인증 (Auth)
- 이메일 + 비밀번호 회원가입 / 로그인 / 로그아웃
  - 비밀번호는 `argon2`(또는 `bcrypt`)로 해시 저장
  - 세션은 **httpOnly + Secure 쿠키**(세션 ID 또는 JWT access/refresh) 사용 — localStorage 저장 금지
- 로그인 시도 횟수 제한(rate limit)으로 무차별 대입 방지
- (선택) 카카오 / 구글 OAuth 로그인
- 로그아웃 시 서버 세션 무효화 + 실시간 연결(WebSocket) 종료

### 3.2 메인 종목 (계정당 1종목)
- 가입 직후 온보딩에서 메인 종목 1개 선택 → `users.main_symbol`에 저장
- **매매는 메인 종목만 가능**, 다른 종목은 조회 전용
- 메인 종목 변경 정책 (택1, 제안은 A):
  - **A. 보유 수량 0일 때만 변경 가능 + 변경 쿨다운 7일**
  - B. 변경 시 보유 주식 자동 전량 시장가 매도
  - C. 변경 불가 (시즌 초기화 때만 변경)

### 3.3 실시간 시세
- 전송 방식: **WebSocket**(양방향, 구독 변경 필요) — 대안으로 SSE
- 구독 규칙
  - 로그인 시 메인 종목 자동 구독
  - 검색 종목 상세 페이지 진입 시 해당 종목 구독, **이탈 시 즉시 구독 해제**
  - 한 연결이 동시에 구독 가능한 종목 수 상한: 메인 1 + 조회 1 (총 2개)
- 트래픽 절감 장치
  - **서버 측 팬아웃**: 외부 시세 소스에는 종목당 1개만 구독하고, 서버가 구독자들에게 브로드캐스트 (구독자 수 ref-count, 0이 되면 상류 구독 해제)
  - **스로틀링**: 클라이언트 전송은 종목당 최대 1회/초 (마지막 값만 전송)
  - **변경분만 전송**: `{s, p, v, t}` 같은 짧은 키의 델타 메시지
  - **탭 비활성화 시 일시정지**: Page Visibility API로 숨김 탭은 구독 해제, 복귀 시 스냅샷 1회 + 재구독
  - 차트 과거 데이터는 REST로 1회 조회 + 캐시(Redis), 이후 실시간 틱만 이어붙임
- 메시지 예시
  ```json
  // client → server
  { "op": "sub", "symbol": "005930" }
  { "op": "unsub", "symbol": "005930" }
  // server → client
  { "s": "005930", "p": 71200, "c": 0.42, "v": 1532, "t": 1760234567 }
  ```

### 3.4 종목 검색
- 종목명 / 종목코드 검색 (자동완성, 디바운스 300ms)
- 종목 마스터 데이터는 DB에 저장해 두고 서버에서 검색 (외부 API 호출 최소화)
- 검색 결과 → 상세 페이지: 실시간 가격, 등락률, 차트 (조회 전용)
- 최근 본 종목 5개 (가격은 실시간이 아니라 진입 시점 스냅샷)

### 3.5 매매
- MVP: **시장가 매수/매도**, 정수 주 단위
- 이후: 지정가 주문, 미체결 주문 관리
- 현실감 옵션: 수수료(0.015%), 매도 시 거래세(0.18%)
- 체결은 **서버의 최신 시세 기준**으로 처리 (클라이언트가 보낸 가격 신뢰 금지)
- 잔고 차감/주식 증가는 하나의 DB 트랜잭션 + 행 잠금으로 처리 (동시 주문 중복 방지)
- 장 마감 시간 정책 (실제 시세 사용 시): 장외 시간에는 주문 불가 또는 다음 장 시가 체결 예약

### 3.6 파산 & 미니게임
- **파산 기준**: `현금 + 보유주식 평가액 < 메인 종목 1주 가격` (= 더 이상 1주도 못 삼)
  - 또는 `총자산 < 초기자금의 1%` 중 큰 값
- 파산 시
  - 보유 주식 전량 강제 청산 → 매매 잠금
  - 파산 횟수 +1 (프로필/랭킹에 표시 — 훈장처럼)
- 미니게임: **주가 맞히기** (실제 과거 일봉으로 출제하며, 정답은 서버만 안다)

| 난이도 | 문제 | 선택지 | 정답 상금 |
| --- | --- | --- | --- |
| 쉬움 | 인기 종목과 실제 날짜를 공개. 20거래일 동안 올랐나/내렸나 | 2 | 100,000 |
| 보통 | 종목과 날짜를 숨김. 5거래일 뒤 종가가 +3% 이상 / ±3% 이내 / −3% 이하 | 3 | 300,000 |
| 어려움 | 종목과 날짜를 숨김. 다음 날 등락률 +2%↑ / 0~+2% / −2%~0 / −2%↓ | 4 | 600,000 |

  - 하이리스크 하이리턴: 어려울수록 상금이 크고, 틀리면 상금 없이 기회만 사라진다
  - **하루 3회, 한 달 10회**. 문제를 받는 순간 차감하고 제한 시간은 2분이다 (일부러 답하지 않아 오답을 피하는 꼼수 방지)
  - 기회 확인과 문제 생성은 INSERT 한 문장 안에서 처리해 동시 요청으로 한도를 넘지 못하게 한다

### 3.7 그 외 화면
- 포트폴리오: 현금, 보유 수량, 평균 단가, 평가 손익, 수익률
- 거래 내역: 주문 시각, 구분, 수량, 체결가, 수수료
- 랭킹: 수익률 / 총자산 / 파산 횟수(명예의 전당)

## 4. 시세 데이터 소스 결정 (중요)

| 옵션 | 장점 | 단점 |
| --- | --- | --- |
| **A. 실제 국내 주식** (한국투자증권 KIS Open API, 키움 REST API 등) | 현실감 최고 | 계좌/API 키 필요, 실시간 등록 종목 수 제한, 장 시간(09:00~15:30)에만 움직임, 데이터 재배포 약관 확인 필요 |
| **B. 실제 암호화폐** (업비트/바이낸스 공개 WebSocket) | 무료·키 불필요, **24시간 변동** | "주식"이 아님 |
| **C. 가상 종목** (서버 시뮬레이션: 랜덤 워크/GBM + 이벤트) | 약관 이슈 없음, 24시간, 이벤트 연출 자유 | 현실 데이터가 아님 |

- 서버의 시세 수집부를 `PriceFeed` 인터페이스로 추상화해 두면 A/B/C를 교체·병행 가능
- 실시간 등록 수 제한이 있는 A의 경우 **서버 팬아웃(3.3)이 필수** — 사용자 수와 무관하게 "서비스 전체에서 활성 종목 수"만큼만 상류 구독

## 5. 데이터 모델 (초안)

```
users        (id, email, password_hash, nickname, main_symbol,
              main_symbol_changed_at, bankrupt_count, is_bankrupt, created_at)
wallets      (user_id PK, cash BIGINT, updated_at)          -- 금액은 정수(원 단위)
holdings     (user_id, symbol, quantity, avg_price)          -- PK(user_id, symbol)
orders       (id, user_id, symbol, side, type, quantity, price,
              status, fee, tax, created_at, filled_at)
stocks       (symbol PK, name, market, is_active)            -- 검색용 마스터
game_sessions(id, user_id, game_type, seed, started_at, ended_at,
              score, reward, verified)
daily_rewards(user_id, date, total_reward)                    -- 일일 상한 관리
```

- 금액은 부동소수점 대신 **정수(BIGINT)** 로 저장
- 시세 최신값/차트 캐시는 Redis, 체결·잔고는 PostgreSQL

## 7. 개발 단계 (마일스톤)

1. **MVP-1**: 회원가입/로그인/로그아웃, 메인 종목 선택, 가상 시세(옵션 C)로 실시간 차트
2. **MVP-2**: 시장가 매수/매도, 포트폴리오, 거래 내역
3. **MVP-3**: 파산 판정 + 미니게임 1종(차트 예측) + 일일 상한
4. **v1**: 종목 검색 + 검색 종목 실시간 조회, 실제 시세 소스 연동
5. **v1.x**: 랭킹, 지정가 주문, 업적, 시즌제

## 8. 추가 아이디어

- **시즌제**: 한 달 단위로 자산 초기화 + 시즌 랭킹 보상(칭호) → 메인 종목 변경 시점으로도 활용
- **같은 종목 단톡방/피드**: 같은 메인 종목을 고른 사람끼리 익명 매매 피드 ("익명의 개미가 100주 매도")
- **파산 명예의 전당**: 가장 빨리 / 가장 많이 파산한 유저 — 서비스 이름과 어울리는 밈 요소
- **업적/뱃지**: 첫 매수, 10% 수익, 상한가 탑승, 3연속 파산 등
- **매매 일지**: 매수/매도할 때 한 줄 메모 → 나중에 차트 위에 표시
- **가격 알림**: 목표가 도달 시 브라우저 알림
- **친구 대결**: 같은 종목으로 1주일 수익률 대결
